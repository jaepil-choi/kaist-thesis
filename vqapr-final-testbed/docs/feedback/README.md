# docs/feedback/

이 폴더는 **평가자가 run이 끝난 뒤 밖에서** 남기는 피드백이다. run 중인 agent가 쓰는 곳이 아니다.

## 이 폴더와 FINDINGS.md의 차이

- `FINDINGS.md`는 **프레임워크가 사용자를 막아 세운 지점**의 기록이다. run 중인 agent가 쓴다.
- `docs/feedback/`는 **run이 끝난 뒤 밖에서 확인된, agent 자신의 replication 오류**의 기록이다.
  vqapr이 막은 것이 아니라 agent가 논문을 잘못 구현한 지점이다.

두 가지를 섞지 않는 이유는, testbed가 측정하려는 것이 replication의 정확성이 **아니기**
때문이다. 구현이 틀렸다는 사실은 그 자체로는 vqapr에 대한 관찰이 아니다. 다만 틀린 구현이
**프레임워크의 표면 때문에 유도되었거나, 프레임워크가 그것을 드러내지 못했다면** 그때는
FINDINGS 항목이 된다. 각 문서는 그 경계를 끝에서 명시한다.

## 다음 run의 agent가 이 폴더를 읽는다면

여기 적힌 것은 **paper와 이 디렉터리 안의 코드만으로 확인 가능한 사실**이다. 바깥 자료를
근거로 쓰지 않았고, 바깥 자료를 가리키지도 않는다. 그러니 이 폴더를 읽는 것은 hard boundary
위반이 아니다. 반대로, 여기 적힌 지적을 "정답 제공"으로 받아들이지도 말 것. 각 항목은 논문의
어느 줄이 근거인지를 밝혀 두었으니, 그 줄을 직접 읽고 판단하면 된다.
